# ADR-0003: 实时协作按阶段引入

## Status
Accepted

## Context

产品希望支持实时协作编辑，但匿名分享、可编辑链接、到期控制、阅后即焚等核心能力本身已经包含较高的产品和工程复杂度。

如果第一版就同时引入完整 CRDT 协作能力，会明显拖慢上线速度，也会抬高系统维护成本。

## Decision

采用分阶段方案：
- 第一阶段先实现可编辑链接、自动保存和基础同步
- 第二阶段再引入 Yjs + 专用协作通道，提供真正的实时协作体验

主应用仍保持单体 Next.js 架构，协作层在需要时再独立增强。

## Consequences

### Positive
- 更快验证匿名 Markdown 分享的真实需求
- 降低首版实现风险
- 避免过早引入高复杂度基础设施

### Negative
- 第一阶段多人同时编辑时仍可能存在覆盖写风险
- “实时协作”体验在早期版本不够完整

### Neutral
- 需要在前端和数据模型上预留后续扩展空间

## Alternatives Considered

### 第一版直接上完整 CRDT 协作

被拒绝，因为：
- 工程复杂度高
- 对匿名权限控制与销毁语义的耦合更强
- 不利于快速上线

### 完全不支持协作

被拒绝，因为：
- 与产品方向不符
- 会削弱“编辑链接”的核心价值
